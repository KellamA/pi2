### Changed
- A message sent to an agent while it waits for a provider's limit now goes with the first request after the wait, so the agent's first answer after the reset reads it. Before, it was read only after that answer. It does not end the wait, which would only be refused again. Until the wait ends it stays queued, where you can take it back, and the message field says so before you send it. Stop still ends the run at any time.

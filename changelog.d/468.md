### For contributors
- Projects (preview, engine only): a project can take its work from an attached GitHub repository, whose issues and pull requests are then its work list, read and changed with the sign-in the Mac's `gh` already has (`engine/src/github.ts`, docs/projects.md 3.11). Every `gh` command names the repository; each write is recorded before it is made and looked for after a restart, and one pi² cannot tell happened is reported, never made again blindly. Agents file, take and finish issues through the same `work` tool, open pull requests from their branch (a fork's too), post findings, and the orchestrator merges under the project's `merge` switch or sends one back to the conversation that opened it. New requests `github.attach`, `detach`, `refresh`, `merge`, `sendBack`, `diff`, `settle` and `projects.watch`, and the `github` event. `PI2_GH` names a stand-in for `gh`; `engine/test/gh-stand-in.mjs` is one. An action of the orchestrator's own no longer counts as news for it, in either kind of list.

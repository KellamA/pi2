### Changed
- A message you send to steer an agent that is waiting reaches it at once. A wait on a sub-chat, on a background command's output or on your answer to its question ends when you send it, and what it waited for carries on: the agent is told the sub-chat is still working, and can wait for it again. If it does not, the sub-chat's answer is added to the conversation when it comes. A command running in the foreground, an edit or a call to an MCP tool is still finished first. Above the message field, pi² says which of the two will happen before you send, and a message waiting says what it waits for. Stop also stops the sub-chats a message let go on.

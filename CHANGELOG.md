# Changelog

What changed in each version, newest first. “For contributors” stays here but is left out of the release notes and the update window.

## Unreleased

What the next version will have is in [changelog.d](changelog.d/), a file for each entry, until a release gathers them here.

## 0.8.7

### Added
- Projects (preview): a worker, a sub-chat of a project's agent, can now put a question or a decision to you under Needs you and carry on working, instead of waiting for your answer. The card says which agent asks, in which sub-chat, and on which piece of work; the sub-chat's name opens it. Your answer reaches the worker while it is still working; once it has finished, the answer goes to the agent that handed it the work, which is told whose question it was and how to continue the sub-chat. A question the worker cannot work on without still waits for you, as before.
- Branches shows the size of each conversation's change, as lines added and removed: what is committed on its branch since it left the branch it was made from, plus what is not committed yet, new files included.
- Settings › General has a **Default model for new agents**, with its thinking level: the model every agent with no model of its own runs on, which is every new agent until you choose one in its settings, whether made by hand, in a project, by an orchestrator, or as a new project's orchestrator. Agents follow it, so changing it changes what they start their next conversation on; a conversation already started keeps its model. Left at **The model used last**, it works as before, following the model you last picked in a conversation; once chosen, picking a model in a conversation changes only that conversation. If the chosen model is switched off or its provider signed out, agents start on another until it is back, and the setting says which. An agent's page now names the model App default stands for.

### Changed
- A conversation shows sooner when it is opened or gone back to: the window no longer rebuilds its whole toolbar each time, and the message field takes the keyboard, and a newly opened conversation's model and tools menus appear, just after its entries show rather than holding them up. Going back to a conversation takes about 35 ms instead of 80, and opening one about 70 instead of 100.
- The `work` tool's `list` now answers one plain line an item — its number, state, class, who has it and in which sub-chat, when it last changed and its title — with a pull request's checks and review in a word, a count by state and when GitHub was read, instead of every item's whole text and every note as JSON. `show` answers one item's line, its text, what finishing it said, and its notes, newest first when there are many, with a long text or note cut and a line saying how many more there are and where to read them. An orchestrator that lists its work often no longer reads the whole backlog's prose at every later turn.
- Projects preview: under an open project in the sidebar, each working agent's row and each of the project's other conversations show, on a quiet second line, the branch it works on with the old sidebar's mark for a worktree of its own or the main checkout, and the size of its change as lines added and removed (`+128 −14`). A working agent in the repository's main checkout on its default branch says so there, in the warning's colour. The title keeps the room: a long agent name is cut in the middle, then shown as the agent's avatar alone. The header of an agent's conversation shown in place of the board, and the Now tab's working rows, show the branch and the numbers too.
- Projects (preview): a project's Work tab opens at once on the list as it was last read, and reads GitHub behind it, with a small spinner by "read … ago" while it does; the rows change in place when the read lands. Reading a repository asks GitHub its questions together, and only for what changed since the last read, and leaves what is closed brief until it is opened: on a repository with hundreds of issues closed this week, a read that took about twenty seconds takes one or two. Opening an issue or a pull request shows what the list knows at once and fills in its text, comments and checks as they arrive, and an action shows at once as on its way, then settles, or is put back with GitHub's words.
- Projects (preview): the Work tab is one calm page, as Notes and Rules are: one line a row, title first, with its number, who has it and when it changed; pull requests in a section of their own above the issues, with their checks and review as small marks; and an opened issue or pull request with its title, one line of where it is, its actions in a bar that stays put, its text drawn as the conversation draws Markdown, and its comments with who wrote them and when.
- Projects (preview): each section of the Work tab's list (Pull requests, Open, In progress, Waiting, Blocked, Done, Dropped) folds and unfolds with a click on its heading, or with the keyboard, and keeps its count while folded. Each project remembers which are folded, after quitting too. Done starts folded, and so do the pull requests merged or closed; the others start open.
- Projects preview: an open project in the sidebar no longer has a row for its orchestrator under it; the project's own row is the orchestrator's. It shows a spinner in place of the project's mark while the orchestrator works, the dot or the hourglass while it waits for you or for a limit, names the orchestrator and its model in its help, and offers Stop the Orchestrator in its menu while it runs. The agents working now and the other conversations follow directly under the project, a conversation that is working is listed once, and the arrow keys go from the project to its first working agent and on through the rows.
- A model newly set up on this Mac answers four requests at once, so four agents can work on it together: each goes on within seconds of its tool finishing instead of waiting for the others' whole turns. Together they write about as fast as one alone, and each request at once takes about 3 GB more memory at a 131K context, which the model's settings now show. A model set up before keeps its setting.
- A new conversation with a model on this Mac thinks at Medium, not Low, unless its agent has a thinking level of its own. On agent steps that needed reasoning, Qwen3.8-Flash-Next thought about half as much at Medium as at Low (whose "keep it brief" made it think longer), and less than at High, and still called a tool every time.
- Projects (preview): each column of the Dashboard now shows a small window onto the conversation with the project's orchestrator, live: its last few turns, with each run of tool calls as one quiet line, over the field that messages it, so a short exchange needs no trip to the hub. The window can be made taller by dragging its top edge or folded away, for each column, and a click on its header opens the hub. Under each column's header, one line says what needs you, who is working (and who waits for a provider's limit, until when), what finished today and how much of it the orchestrator has not read, and what the project spent today against its limit; each part opens the hub where it is shown.
- Projects (preview): a Dashboard column also shows what finished today, folded with its count and how many reports the orchestrator has not read, and, for a project whose work is a GitHub repository, the pull requests waiting to be merged, each with its checks and review in a word; a click opens one on the Work tab. A line across the top counts what needs you in all (⌥⌘0 brings the first into view), who is working and what was spent today, with each subscription's windows and a mark while a provider refuses for its limit. Columns can be put in your own order by dragging their headers, or folded to a narrow strip, and ⌥⌘1 to ⌥⌘9 put the keyboard in a column's field.

### Fixed
- Work assigned through a project's work list started the agent's sub-chat in the project's own folder: the repository's main checkout, on `main`, beside every other worker, with nothing to keep two agents' changes apart. `assign` now gives its sub-chat a git worktree of its own — named for the work, such as `work-12-tidy-the-login-form`, when the project's folder is a repository — as `delegate` does, with `worktree` and `from` to name the branch yourself, `worktree: false` to keep it in the project's folder, and the person asked where `delegate`'s worktree would ask. Its answer says which branch the sub-chat works in, and the Work tab's row shows it.
- The Work tab's Give to menu showed each agent as the first letter of its name and nothing else, so agents whose names begin alike could not be told apart and work could not be given to the one meant. Each row now shows the agent's whole name with its avatar before it, in the list pi² keeps, in an opened piece of work and on a GitHub repository's issues. The Agents tab's From a Template menu shows each template's avatar beside its name the same way, and the Rules tab's menu of whom a rule binds ticks the one chosen rather than putting a tick character in its name.
- Projects preview: an agent keeping its work on a GitHub repository's issues with the `work` tool can now post its summary with `finish` once a merged pull request has closed the issue, where it was refused before; `finish` and `close` take the status label off the closed issue.
- Projects preview: only the orchestrator gives a filed item a class (another agent's is left out, and it is told so); an issue taken or paused outside the tool, with `scripts/issue`, is refused saying so and that the orchestrator's `release` hands it over; an agent taking work it already holds is told so rather than refused; `resume` posts a line on the issue; the issues agents file and take carry the `agent` label; and every text the tool posts on GitHub has the home folder written as `~`.
- A sub-chat of an agent whose settings give each conversation a git worktree of its own now gets one whether `delegate` or the orchestrator's `assign` starts it; before, `delegate` gave it none unless asked, and the person was not asked either. An assignment past a project's limit no longer makes a worktree and branch before it is refused.
- A model on this Mac answering several requests at once no longer stops itself when two answers are written side by side for more than a minute ("no progress for 60 s during a request"). The cause was in Strata's engine, which did not count that work as progress on a Mac; pi² now uses Strata 0.2.17, where it is fixed. Update Strata in Settings › Providers › On this Mac: until then, a model runs one request at a time whatever its setting, and the setting says so.
- An agent working with a model on this Mac had its whole conversation read again whenever one of its background commands started or ended, since the list of them is part of its instructions: up to a minute and a half each time on a long conversation, and over an hour across six tickets one night. The change is now sent where it happens, so the model reads only what is new.

### For contributors
- An agent working on pi² in a pi² project keeps its issue with the project's `work` tool, and every other agent with `scripts/issue` as before: `CLAUDE.md` has a table of the two side by side, and `docs/agents.md` follows it. Once a merge has closed an issue, the tool's `finish` refuses it, so the summary goes on as a note beginning `**Done.**`. `scripts/issue audit` now counts the tool's summary, which begins with a line naming the agent, as a `**Done.**` summary.
- `pi2-window-check` now reads what the projects screens' pop-up menus come out as in a native menu, without showing one: each menu is made as the app makes it, with the rows of the new `MenuKit` module, filled as AppKit is about to show it (or, for a menu with a button style of its own, pressed through accessibility with NSMenu's pop-up kept off the screen), and every row must be the whole name it stands for, an agent's with its avatar. It also fails on a menu in the app's sources whose rows are made of stacks, shapes or `AgentAvatar`, which a native menu does not draw. `--menus` runs only that part, and `--menu-pictures <folder>` draws the rows as read, dark and light (#597).
- `scripts/test-copy can-click` said a throwaway copy could not be clicked ("the main window did not join the app's accessibility window list when raised") while the computer tool read and clicked that same copy. The copy judged by its app's window list, which a parked window drops out of whenever AppKit stops counting it as on the active Space, while the tool reaches it as the app's main window throughout. The copy now answers from every attribute the tool's search reads, and `can-click` has three answers: yes (exit 0), no with its cause (exit 1), and "cannot tell from here" (exit 2) for a copy that did not say or a build that predates the request. It also waits up to 30 seconds for a copy just started or reopened to draw its window rather than saying it has none (#612).

## 0.8.6

### Added
- With the Projects preview on, a project's board has a Now tab: what needs you, answered in place; who is working now, with a switch for whether reports wake the orchestrator; and what finished today, marked when it has not been read yet.
- Clicking one of a project's other agents opens its conversation in place of the hub's board, with a way back to the board, so the person can watch or message a worker and still talk to the orchestrator — part of the projects preview.
- In a project's conversation, part of the projects preview: each change the orchestrator makes through its tools shows as a quiet line with Undo, which reads as undone once it is, and a request for more reach or a proposed rule shows as a card answered in place; exports say both.
- With the projects preview on, the Agents tab of a project's hub shows the orchestrator with the switches of what it may do without asking, the project's other agents with their pages and Update from template, the agents a tool removed with Restore, and the way to the templates. Part of the projects preview.
- The board's Rules tab, part of the projects preview: the project's rules listed and edited in place (add, edit, reorder, remove, whom each binds), what they add to every request in tokens, and a card to accept, edit or refuse a rule an agent proposes.
- With the projects preview on, a project's hub has a Notes tab: what its agents have noted about the project, to read, correct, remove and add to, with a search over them and a way to share a private note with every agent.
- With the projects preview on, a project's board has its last two tabs: Settings, where the project's own settings are changed (its name and folder, the attached repository, the orchestrator's model, whether reports wake it, and the limits that hold back starts, plus archiving and deleting), and Branches, the branch tracker for the project's conversations alone. Part of the projects preview.
- A project's Work tab, part of the projects preview: the project's work as pi² keeps it, grouped by state, with a new piece of work, notes and result on one opened, giving a piece to an agent (which starts it, confirmed past a limit) and the actions the state table allows.
- The Work tab of a project whose work is a GitHub repository now shows that repository's issues, grouped by state and opening to their text, comments and the actions the contract gives the person, and its pull requests with their checks, what a reviewing agent found, Diff, Merge and Send back, with one calm line at the top when GitHub cannot be reached: part of the projects preview.
- With the projects preview on, the Dashboard shows the projects you tick, a column each — what needs you, answered in place, who is working, the orchestrator's last words and a field to message it — and the menu bar's count, the Dock badge and its list follow the projects' needs in place of the Inbox.
- A conversation of a deleted project can be restored from the Archive into the project of its folder, with its sub-chats, under a copy of its agent (part of the projects preview). The Archive lists a deleted project's conversations under it, each with a Restore to a Project… action that shows what would happen first: where the conversation goes, which agent it runs as, and what the copy takes.
- A conversation's model that cannot see pictures can have one looked at by a model that can: choose a **Model that looks at pictures** beside the picture model, and such a conversation's agent gets a `look` tool that answers its question about a picture file in words, with the spend shown in Usage under that model. Where a picture would have been given to a model that cannot see — `read` on one, a screenshot — it is now told so in one line and asked to use `look`, and the picture's bytes are not sent to it.
- While any conversation is working, or waiting for a provider's limit or the network to carry on by itself, pi² now keeps this Mac from going to sleep by itself (the display can still sleep). The switch is in Settings › General, on by default, with "Also on battery" under it; the sidebar's "Engine running" line says when the Mac is being kept awake. Closing the lid of a Mac with no display attached still puts it to sleep, which no app can prevent.
- A file tool can be given a path in the conversation's scratch folder. `read`, `write`, `edit`, `list_files`, `find_files` and `search_files` take a path beginning with `$PI2_SCRATCH` or `${PI2_SCRATCH}` as that folder — the same one a shell command's `$PI2_SCRATCH` names — and say what they found there: `read`, `write` and `edit` answer with the real path, which can be used again, and `list_files`, `find_files` and `search_files` name what they list, find or search `$PI2_SCRATCH/…`, which can be given straight back as the path. A path beginning with any other `$` is refused and says so, which is what stops a folder named `$HOME` being made by mistake; a `$` in the middle of a path is still just a character in a name.
- The Work tab of a project's GitHub repository names a pull request's failing checks and counts them on its row (“2 checks failing”), and the opened pull request lists them, each opening its page on GitHub. A finding a reviewing agent posted shows its own words under the verdict, and `github.unknown { projectId }` lists the writes whose outcome pi² could not tell, with the id each is settled by, for a script or a test copy (part of the Projects preview).

### Fixed
- A command an agent runs could widen its own reach through the engine's socket: `agents.save` with full access, a conversation's access, an allowed command, a variable, an MCP server, a schedule and the like were taken from any connection, without answering anything. They are the person's own settings, and are now refused from any connection but the pi² app's, as answers to approvals and questions have been since #504; the app, and `scripts/test-copy` with its key, keep making every one of them.
- When a provider closed the stream before or during an answer — HTTP/2's `ENHANCE_YOUR_CALM` or a refused stream, or a connection reset — the run stopped for good and had to be carried on by hand. Now it waits and asks again by itself, as it does for a network that is away, beginning at the longer waits when the provider asked for less; the conversation says the provider closed the connection rather than that the network is gone, and nothing the model had written is kept twice.
- A project hub's bar drew its orchestrator’s model menu (“Orchestrator · <model>”) in the system button’s own colour, which in light appearance was white on the pill’s white: it read as an empty pill, on the board and with an agent in its place alike. Its words are the bar’s colour now, and read in either appearance.
- Choosing a project with the arrow keys in the sidebar opens its board, as a click does. Earlier, a project whose agent’s page had been opened earlier in that launch could open on that agent instead.
- A working agent’s row in the sidebar says one thing rather than two sentences run together: “Open this agent’s conversation in place of the board”.
- A conversation shown in place of the board that stops working no longer moves into the folded “other conversations” group and hides its marked row: the group stays open while one of its conversations is the one shown.
- A project’s Work tab: its work’s “Give to” menu no longer lists the project’s orchestrator or an agent a tool removed, since neither can take the work, and every row shows the agent’s face as the rest of the hub shows it.
- An opened piece of work says where it is and offers what its state allows above its text rather than after it, so they are to hand however long the text is.
- When a project’s setting asks each time for something an agent wants to do, the request in the conversation now offers only Allow Once and Deny, as the Now tab’s card does. It offered an “always allow” as well, which the engine refused, since only the project’s Settings can stop the asking.
- In a project's Work tab for a GitHub repository, Send Back's field was drawn with a border inside the panel's, two borders where the Notes and Rules tabs' fields have one. It now has the one.
- Manage Templates… on a project's Agents tab opened the first template's page even when another template's page was on screen. It now unfolds the sidebar's Templates and leaves the page that is showing.
- The orchestrator's `project_settings` tool refused a limit given by the name the project's own fields have (`planShare`, `dailySpend`) as an unknown field. It takes either name now.
- When one conversation is refused for a provider's limit and the refusal names when it resets, the other conversations on that provider now wait for the same time instead of each asking and being refused: one request is let through when the time comes and the rest follow when it is answered, Stop and Carry on still end the wait, and the agent that hands out work is told the provider's limit is used up until then.
- A run refused because a plan's five-hour window is used up (OpenCode Go's "resets in 2h 17m") now waits for the reset and carries on by itself instead of ending.
- A model that sent a tool argument that should be an array or an object as a JSON string of it (`edit`'s `edits`, `update_plan`'s `items`) had the call refused with “expected object, got string”. The string is now read as the value it encodes before the arguments are checked, for every tool alike: the result tells the model to send the value itself next time, the call's row says so in a few words, and the engine's log names the tool and the model, so it can be counted.
- `edit` answered "Successfully replaced" for an `oldText` that was not in the file exactly — one wrong quotation mark was enough — and wrote the agent's slightly wrong text over a line the change never meant to alter, losing the file's own characters on the lines it touched. Such a near miss is now refused with the file's own text for the place it nearly matched, so the agent can send it again exactly; an exact match is applied as before, and a file's own line endings keep their tolerance.
- The computer tool could read no controls and no text from a throwaway copy's window, and answered every click at a point with "Nothing in the window appears to have changed" even when it worked: a copy's parked window, never having been raised, is left out of the app's accessibility list entirely, and the fingerprint the click was checked against was of an empty list of controls. The tool now asks the copy to raise its window once within its own level — behind every other window, so nothing appears on screen — and reads it like any app's window afterwards; when a copy cannot, the answer says what is wrong and what still works instead of blaming the app. `scripts/test-copy can-click <suffix>` answers before a review whether computer use can reach a copy, and which cause if not (#579).
- The activity pills are drawn with AppKit views now, with no SwiftUI in them: the app could still crash while agents used the computer, even after 0.8.5's fix, because SwiftUI sizes the window of the view it hosts. A pill is sized from its label once, at the widest the screen allows, and changes that arrive together make one resize.

### For contributors
- `scripts/auto-merge` merges a pull request whose required checks have all passed already, where it used to fail with "Pull request is in clean status"; `scripts/test-auto-merge` checks it with a stand-in `gh`, and CI runs it with the other scripts' tests.
- `scripts/test-copy show` takes every page `--show` takes, such as `usage`, `archive` and `settings:<tab>`, and answers once a conversation's page or a hub has drawn it, or says plainly that it cannot wait for the page it switched to.
- `scripts/test-copy answer-of <suffix> <conversation> <submission>` reads the answer of a submission whose run was still going when `send`'s wait ended, without sending the message again.
- `scripts/test-copy start|reopen --appearance light|dark` draws a copy in that appearance whatever the Mac's own is, so that a page can be pictured in both.
- `scripts/test-copy show … '#agent:<name>' --hub board-folded` says that it unfolded the board, which the copy's preferences keep.
- The workers' brief says how to write a path in the scratch folder, where to keep pictures of a throwaway copy, and how a reviewer brings another agent's branch up to date; the architecture page no longer says releases are unsigned.
- `npm test` in `engine/` now takes its list of test files from a program, `engine/scripts/test-files.ts`, as CI's two groups do, and checks after the run that every file in the list reported: a file that did not report ends the run with an error naming it, even when every test that ran passed. Node counts a file that ends as a pass, so a file that was never run, or that ended before its tests reported, used to pass silently (#577).
- `engine/scripts/patch-dependencies.ts` refuses a tree it has already patched, where a second run used to apply some patches twice; `npm --prefix engine ci` installs and patches afresh.

## 0.8.5

### Added
- Part of the Projects preview: **Projects (preview)** in Settings › General. Turning it on first shows what would be carried over into projects (each project, what goes into it, every copy of an agent that takes its variables' values or Allow everything, by name, and anything to know), and does it only once you go ahead. With it on, the sidebar lists projects in place of agents and conversations: each with a badge for what needs you or how many agents are working, the open one with its orchestrator, the agents working now and its other conversations, then the agent templates and the Archive. Projects are made from a folder in one step, renamed and archived from the sidebar, restored from the Archive, and found with ⌘K. Turning it off shows everything as it was, and the agents' list leaves out the agents that belong to projects.
- Part of the projects preview: a project's hub, with the conversation with its orchestrator on the left and the board on the right. Each panel folds with its own button and key (⌥⌘[ for the conversation, ⌥⌘] for the board), and each project opens as it was left. With the conversation folded, a strip along the bottom of the board keeps the orchestrator's last words and a field to answer it; a window too narrow for both panels folds the board by itself and says so. The bar above shows the project, its folder and branch, the orchestrator's model (choosing another changes the orchestrator's agent), and how much of the plan's week is used. The board's tabs (Now, Work, Agents, Rules, Notes, Branches, Settings) say what each will show. A project carried over whose orchestrator was never opened gets its conversation when its hub first opens.

### Fixed
- Summarising long conversations now gives the summary its own output budget with thinking off or at its lowest, and tries once more for a shorter summary if the model runs out of room. After a failed automatic summary, pi² waits for both time and context growth before trying again. The banner offers a retry with a note and can be dismissed.
- Prevent the computer and browser activity pills from driving window layout, which could crash pi² while agents worked. Long names now shorten in the middle instead of making a pill wider than the screen.

### For contributors
- The engine's type-check and tests now stop at once, with one line saying what to do, when the installed dependencies were patched from an older checkout than the one they run in: a worktree that merged `main` without running `npm --prefix engine ci` again, where tests used to fail in ways that said nothing about the change being tested.

## 0.8.4

### Added
- Choose which model makes pictures in Settings › Chat. Usage shows picture spend by model and says when the price is unknown.

### Fixed
- A command an agent ran could connect to pi²'s engine as the app does and answer approvals and questions itself, its own included, or turn on Allow everything. Now the engine takes those answers only from the pi² app, which it tells from any other program by macOS's code signature, and an agent that tries is told to ask you. A command can still change an agent's settings that way, or write pi²'s data folder; see "Who may answer for the person" in docs/architecture.md.
- A brief network outage no longer ends a run. pi² waits and tries again for up to about ten minutes, shows when work carries on, and keeps messages sent while it waits.

### For contributors
- The engine knows projects (#456, the first step of the projects epic, [docs/projects.md](docs/projects.md)), behind a preview switch that nothing in the app turns on yet: `projects.setPreview { on: true }` through a throwaway copy's engine (`scripts/test-copy call`) does. With it on, `projects.create` makes a project from a folder in one step, with its orchestrator and an empty conversation with it, and `projects.rename`, `projects.set`, `projects.archive`, `projects.unarchive`, `projects.delete` and `projects.list` work, with a `projects` event for the apps. With the preview off, every request that exists today works as before and a conversation in no project is told exactly what it was told.
  `engine/src/projects.ts` holds what the later issues of the epic build on (`projectsOn`, `inProject`, `requireSwitch`, `addNews`, the `admit` stub) and the places they fill in. The demo model answers `/system full` with the whole prompt and every tool declaration, for tests that compare them.
- Projects preview, step 2 (#457): agents that belong to a project, and templates (the agents of no project). The engine copies a template into a project (`projects.addAgent`), says what Update from template would change and changes it (`agents.updateFromTemplate`), and puts back an agent removed through a tool (`agents.restore`); `agents.save`, `agents.duplicate` and `agents.delete` handle project agents. Every lookup of a conversation's agent goes through `runsAs` (`engine/src/state.ts`), which the `library` and `activity` events now carry, and `delegate` in a project names only the project's agents, asks first while `startAgents` is off and calls `admit`. Nothing changes with the preview off, and nothing in the app yet; see `docs/projects.md`.
- Projects (a preview): the engine can carry today's agents and conversations over into projects (`engine/src/carryover.ts`, docs/projects.md section 9). `projects.carryOver` with `dryRun` reports what would go where, with a fingerprint; turning the preview on runs that plan only if it is still the same, after a backup, one project per commit, so a second run changes nothing. Agents are copied into each project, with their notes for the copy alone (recorded per project, so a project that gets a copy later gets them too) and their variables' values copied into the Keychain in a step retried at every start and with `projects.retrySecrets`. A project given the default orchestrator gets its conversation only when it is first opened (`projects.startFresh`). Conversations made later with the preview on, forks among them, go into their folder's project, checked against its limits; one left in no project is carried at the next start. A conversation whose project was deleted is in no project: it runs as its own agent, hands work to templates and reads its agent's notes. Nothing the old screens read is changed, so switching the preview off shows everything as before. Tests that need a conversation in no project with the preview on use one whose project was deleted (`previewOnLeavingOut` in `engine/test/patience.ts`).
- Add the project rules document, preview requests and event, and a persistent prompt section with token estimates for each binding. The app does not expose rules yet.
- Add project-scoped memory to the Projects preview engine, with note audiences and the handoff for recording agent changes and Undo.
- Projects preview, step 2 (#462): Needs you in the engine (`engine/src/needs.ts`), one list for everything that waits for the person, as `docs/projects.md` 3.9 says. Approvals and `ask_user` questions from the Inbox and needs stored in `pi2.needs` are sent in the `needs` event and answered with `needs.list` and `needs.answer`. Every answer, `inbox.decide` and `inbox.answer` included, goes through one function, `claim`, which takes an item exactly once; a second answer to an item now gets "This is no longer waiting: it was answered or withdrawn." A project's own conversations get the tool `needs_you`, to put a question or decision and carry on, and the answer wakes them as a wake of the new kind `answer`. Later issues plug in what answers to reach requests, proposed rules and limit cards do with `onAnswer`. With the preview off, nothing changes.

- **Development builds keep apart from the installed pi².** `./app/build.sh` now makes `pi² dev.app`, with its own bundle id, data folder and Keychain service, and will not use the installed copy's usual data folder or service even if inherited environment variables name them. A development build never updates itself or changes the installed copy's login item. Give concurrent test copies their own bundle ids as [CONTRIBUTING.md](CONTRIBUTING.md) describes.
- **Optimised development builds.** `./app/build.sh optimised` compiles with release optimisation but keeps the development build's isolation, window placement, `PI2_SHOW`, hidden drawing and web inspector. `release` still makes the self-contained app with none of those test affordances.
- **Packaged start-up is checked before a release is drafted.** The release workflow starts the engine from the actual update archive and mounted disk image, checks its build, gets a scripted answer and stops it cleanly; it also opens the app from the archive and checks that it connects. Ordinary CI builds an ad-hoc release app and proves the same check and deliberate missing-file and wrong-build failures. No release keys are needed for that check. See [docs/releasing.md](docs/releasing.md).
- Engine tests now measure clean shutdown inside the engine, keeping the real five-second deadline, and wait for committed state before crash-recovery checks instead of sleeping. Background-output checks must see new output, not merely reach a wait's time limit.
- **Keep reader-facing changes first.** New changelog sections can keep build, test and repository changes under For contributors without putting them in GitHub's release notes or the update feed. The extraction is tested in CI; already-published sections are left unchanged.
- **`PI2_SHOW` opens archived conversations.** A development build started with `PI2_SHOW` set to a number or title now finds archived conversations and archived sub-chats too, after the ones in the sidebar. It opens them as they are and does not restore them. See [docs/development.md](docs/development.md).

## 0.7.6

### Added
- **Read what a background command prints.** Activity's rows for background commands have an Output button, which opens a window with the command, its conversation, whether it is still running or how it ended, and what it has printed so far, kept up to date as more arrives. You can select and search the text, and stop the command from there. Reading it does not take anything away from what the agent has yet to read.
- **A conversation shows the commands it has running.** Above the message field, a strip names the background commands the conversation and its sub-chats have running, each with how long it has run, Output and Stop. The menu bar's Running list names them too.

Background commands they left running are stopped first, and the conversation says what was archived.
- **A sub-chat can have a worktree of its own.** When an agent hands work to another, it can ask for a git worktree and branch for the new sub-chat, starting from the commit its own folder is on or from one it names. The sub-chat works there, the receiving agent's set-up command runs first, and the sidebar and Branches show it as the sub-chat's own worktree.

### Changed
- **Every sub-chat shows its branch in the sidebar.** A sub-chat working in the same checkout as its parent used to show no branch icon. It now shows one, faded, in the colour of how the branch stands; a sub-chat with a worktree of its own, or in another repository, shows it at full strength.
- **When the engine cannot be started, the window says so.** After three starts in a row have failed, a notice at the top of the window says how the last one ended and shows the end of `engine.log`, with what to check, Try Again and a way to find the log. pi² keeps trying on its own, less and less often, and the notice goes as soon as an engine answers. Before, the footer said "Starting engine…" for ever.
- **After an unexpected engine stop, Activity names the commands that were left.** Its notice now lists the background commands and worktree set-up commands the last engine left running, and what became of each: stopped, already over, or left alone because pi² could not be sure it was the same. ### Fixed

- An approval asked again after the engine restarted could come back without its "always allow" choice, and a command a saved rule covers could be asked about anyway. It happened when the last engine had left a background command or a set-up command running.
- An engine told to stop while it was still starting (quitting pi² right after opening it, say) was killed outright, so the next start reported a crash that had not happened and the login shell it was asking for its `PATH` was left running. It now stops cleanly.

## 0.7.5

### Added
- **Commands left running in the background.** An agent can start a command and carry on while it runs (a development server, a watching build, a test copy of an app), read what it prints later, and stop it. Starting one asks the way any command does under Ask first, says in the approval that it will keep running, and is covered by Always Allow and by command rules. It has no time limit; it runs until it ends, the agent or you stop it, its conversation is archived or deleted, its worktree is removed, or pi² stops. Activity lists what is running, each with a Stop button, and the conversation says when one ends. After a crash, the next engine stops what the last one left running. See [docs/background.md](docs/background.md).
- **A set-up command for new worktrees.** In an agent's settings, under Give each conversation its own worktree, a command such as `npm ci` runs once in each new worktree of that agent's conversations, right after pi² makes it, so what git ignores is put back. The conversation shows it running, then its output and whether it failed; the first answer waits for it, and the agent is told how it went. See [docs/worktrees.md](docs/worktrees.md).

### Changed
- `app/build.sh` stops before building when a copy of pi² is running from the bundle it would replace, and says which process and what to do instead; `PI2_REPLACE_RUNNING=1` replaces it anyway. [docs/development.md](docs/development.md) has a new section, "Working on pi² with pi²".
- **A test copy of pi² can be looked at.** Computer use no longer refuses every app whose bundle id starts with `dev.pi2.app.`: such a copy is look-only, like browsers and System Settings, so an agent working on pi² can check a change by looking at a throwaway build. pi² itself (`dev.pi2.app`) still cannot be given to an agent.
- **Project instructions from the repository's top.** A conversation working in a subfolder of a git repository is now given the `AGENTS.md` or `CLAUDE.md` of each folder from the repository's top down to its own, the top's first, so the nearest has the last word. Nothing above the repository's top is read, and a folder in no repository reads only itself, as before. The 24,000-character cap is shared between the files. See [docs/knowledge.md](docs/knowledge.md).
- **Commands have a time limit.** A command an agent runs is stopped after 30 minutes, so one that never finishes no longer holds the conversation until you stop it. The agent is told the limit, can ask for longer for a command it knows is slow, and is told when the limit stopped one. A command that waits for typed input fails at once instead of waiting.
- **Command rules reach worktrees.** A rule made in a repository's main checkout, or in any worktree pi² made from it, now holds in the same folder of all that repository's pi² worktrees, for the same agent, so a conversation in a new worktree no longer asks for `npm test` again. A rule made in a worktree is kept for the main checkout's folder. Worktrees pi² did not make are not affected. See [docs/rules.md](docs/rules.md).
- **A worktree's set-up command shows its output as it runs**, as a command an agent runs does, rather than only once it ends. A set-up left running by an engine that crashed or was killed is now stopped when the engine starts again, when pi² can tell it is the same process, and the conversation says what happened. A command still running when you open its conversation now shows its newest output, not its first lines. See [docs/worktrees.md](docs/worktrees.md).
- **A sub-chat working in its parent's worktree says so.** Branches lists it under the conversation whose worktree it is, marked "parent's worktree" rather than "worktree"; its tooltip, its toolbar's branch menu and the branch details name that conversation. **New Worktree…** for such a sub-chat says that the new worktree starts from the parent's branch and that the sub-chat stops working in the parent's worktree. See [docs/worktrees.md](docs/worktrees.md).
- **A command's approval says how far its rule reaches.** When the rule it offers also holds in the repository's main checkout and its pi² worktrees, the button reads "Always Allow `npm test` in This Repository" instead of "…Here", in the conversation and in the Inbox, rather than saying so only when hovered. A long command is cut short in the button so the rest of the label still shows. See [docs/rules.md](docs/rules.md).

### Fixed
- An agent's commands could not find programs you installed yourself, such as `node`, `npm` or `gh`: they ran with the bare `PATH` macOS gives an app. The engine now takes its `PATH` from your login shell when it starts, so commands, MCP servers and git find what a terminal window would.
- When your login shell took more than five seconds to give its `PATH`, as it can right after login, the engine stopped it and ran with a few usual folders until its next start, so an agent's commands could fail with "command not found" or find another version of a program, with only a line in `engine.log` to say why. The engine still starts after five seconds with the usual folders, but now lets the shell finish and takes its `PATH` when it answers: commands, git and MCP servers started from then on get it. A command or MCP server already running keeps what it started with; reconnect the server in Settings to give it the new one. A shell that has not answered after five minutes is stopped.
- An agent could not look at a picture larger than 2,000 pixels or 4.5 MB with `read`, such as a screenshot of a window on a Retina display, and could not read BMP at all. `read` now scales such a picture down to fit, converts BMP, and tells the agent the size before and after.
- A conversation working in a worktree that handed work to another agent got a helper working in a different checkout, often the main one. A new sub-chat now starts in the folder its parent works in, worktree included, and is told so, unless the other agent's own folder is in another repository. See [docs/worktrees.md](docs/worktrees.md).
- Computer use compared bundle ids with regard to case, though macOS does not, so an agent given `com.apple.terminal` or `Dev.Pi2.App` could get past the lists that refuse `com.apple.Terminal` and `dev.pi2.app`. Every comparison, in the engine and in the app, now ignores case: the never and look-only lists, the check that a call names an app the agent was given, the app refusing itself, an agent's list of apps, and allowing an app for the rest of a conversation. See [docs/computer-use.md](docs/computer-use.md).
- A copy of pi² on a data folder of its own (`PI2_HOME`), such as a test copy, could turn off the login item and so stop the engine of the copy in real use, or replace it with one that started its own engine on the usual data folder. The login item can now be installed only by a copy on the usual data folder, and replaced or removed only by the copy whose data folder it serves; elsewhere the switch in Settings › General is unavailable and says why.
- A failed set-up command's row put the command first, so with any real command the reason was cut to "exited …", and its opened output was all red, standard output included. It now leads with what happened ("Set-up command failed: exited with code 3") and shortens the command instead, repeats the reason on a line of its own above the output, and shows the output in the ordinary colour. The one-line text other views and the Markdown export use also lead with the reason. See [docs/worktrees.md](docs/worktrees.md).
- Opening pi² with the window split into panes often showed "Something went wrong: The engine is not running yet." although the engine was running: the panes asked for their conversations before the app had connected. A conversation opened before the app connects now waits for the connection and opens then.

## 0.7.0

### Added
- **Worktrees.** A conversation in a git repository can move into a worktree of its own, on a new branch, so several agents can change one project at once. An agent can be set to start every conversation in one. Removing a worktree takes the conversation back to where it was and keeps a branch with unmerged work. See [docs/worktrees.md](docs/worktrees.md).
- **Branch tracker.** Each conversation working in a git repository shows its branch next to it in the sidebar and in its toolbar: a plain icon for the main checkout, a boxed one for a worktree, coloured by how the branch stands (changes, commits to push or merge, merged, conflicts). Branches in the sidebar lists them all by repository.
- **Worktrees left behind.** Deleting a conversation offers to remove its worktree too, when nothing in it is uncommitted. Branches lists the worktrees of archived and deleted conversations under Left Behind, each with a Remove button.
- **Split panes.** The conversation area splits into up to 16 panes, each with its own conversation. Ready-made layouts (two, three even or one big with two half-size, grids up to four by four) are in the toolbar's Layout button and View › Layout; Split Right (⌘D) and Split Down (⇧⌘D) make any arrangement in between. Dividers drag to any size, and double-clicking one evens it out. The focused pane's conversation is the one the title, toolbar, sidebar and Conversation menu follow; ⌘] and ⌘[ move between panes and ⌃⌘W closes one. A conversation can be dragged in from the sidebar, and the layout is kept between launches.
- **Sub-chats beside their conversation.** A hand-off in the transcript has a Beside button next to Open: it splits the pane and shows the sub-chat next to the conversation that opened it, so you can watch both. A sub-chat already on screen is moved to instead.

### Changed
- **Plan limits stay current.** Opening Usage checks again any signed-in subscription whose figures are more than an hour old, without waiting for Check Now.
- **Model pickers name the provider.** An agent's model picker lists models under their provider, like the chat model menu, and names the provider when closed. Two providers offering a model with the same id no longer get their rows mixed up, and an agent whose model has since been hidden shows it as "(hidden)" instead of a blank picker.

### Fixed
- After saving one of the starter agents, Save and Revert stayed lit and New Conversation stayed off, because saving fills in settings the starters were made without. The agent page now compares an agent as it would be saved.

## 0.6.0

### Added
- **A new transcript.** The conversation is one page in the style of Claude Code: answers as plain text with full Markdown, tool steps as single lines that open to their output or diff, approvals and questions where the agent stopped. A selection runs across prose, code and tool steps and copies as clean text. See [docs/transcript.md](docs/transcript.md).
- **Archive.** A conversation can be archived instead of deleted: it leaves the sidebar with its sub-chats, stays readable and searchable, and can be restored. Conversations left unused for a chosen time can be archived automatically. See [docs/archive.md](docs/archive.md).
- **Downloads and updates.** Release builds are signed, notarized and packaged as a disk image by a workflow that runs on a version tag. A downloaded copy can update itself (Sparkle), only after you agree to checks, and only to updates signed with the project's key. Before an update the engine is stopped cleanly, and the new app replaces an engine left over from the old one. See [docs/releasing.md](docs/releasing.md).
- **Command rules.** An approval for a shell command can allow commands that start the same way from then on, for that agent in that folder. Compound commands, writes to files, variables and anything else not plainly covered still ask, and rules that would allow anything cannot be made. Rules are listed in the agent's settings. See [docs/rules.md](docs/rules.md).
- **Agents can schedule their own work.** Off by default per agent. Each schedule is approved by you before it is made, shows in Activity as set by the agent, and the agent can cancel only its own. See [docs/schedules.md](docs/schedules.md).
- **Formatted documents.** An agent that may write files can write a Word, RTF, OpenDocument or HTML document from Markdown with `write_document`, with the same approval as any other write. See [docs/documents.md](docs/documents.md).
- **Computer use.** An agent can see and work the apps you choose, one window at a time, in the background, asking before it acts. See [docs/computer-use.md](docs/computer-use.md).
- **A browser of the agents' own.** An agent can open pages, search, read, click, type and upload in pi²'s own browser, which keeps its sign-ins apart from Safari and Chrome. You can watch and take over in the Browser window. See [docs/browser.md](docs/browser.md).
- **Plan limits.** For a subscription you are signed in to, Usage shows how much of each of the provider's windows is used (for example 5-hour and weekly) and when it resets, for Anthropic, OpenAI Codex, GitHub Copilot and Kimi. These come from interfaces the providers do not document; see [docs/limits.md](docs/limits.md).
- **Project instructions.** An agent working in a folder that has an `AGENTS.md` or `CLAUDE.md` is given it, read fresh for every message.
- **Memory.** Per agent and off by default: the agent keeps short notes between conversations with `remember` and `forget`, and you can read, edit and delete them in its settings. See [docs/knowledge.md](docs/knowledge.md).
- **Tools for looking around.** `list_files`, `find_files` and `search_files` for any agent that may read its folder, and `web_fetch` and `web_search` for agents with the browser switched on. None of them changes anything or needs approval. See [docs/look.md](docs/look.md).
- **A task list.** For work with several steps an agent keeps a checklist, shown above the message field. It survives restarts and forks. See [docs/plan.md](docs/plan.md).
- **Pictures and files in chats.** Paste, drop or attach pictures, text and code files, PDFs and Word documents. A model on your own endpoint can be marked as able to see pictures. See [docs/attachments.md](docs/attachments.md).
- **Sub-chats.** Each handoff to another agent opens a chat under the conversation that started it. An agent can continue an earlier sub-chat instead of starting a new one.
- **Reference files.** Files and folders an agent can always read, opened on demand.
- **Model picker per provider.** Choose which models show in the menus. Search by name or id, Select All and Deselect All (which act on the search's matches while one is typed), and "Newest Only", which keeps one of each family. A provider may have every model unticked.
- **A new look.** A dark-first palette, with light and match-system in Settings › General.

### Changed
- Delete is now separate from Archive and says what it does: pi² stops showing the conversation and cannot bring it back, and its text stays in pi²'s data file.
- Reference files can be Word, RTF and OpenDocument files; the agent is given their text.
- Usage from a subscription sign-in, or from a local model, counts tokens only. It shows no cost and does not count toward the daily budget.
- Usage names models as "Provider · Model".

### Fixed
- A step you declined read "Ran … Failed" in the conversation. It is now crossed out and marked as declined.
- Switching on hand-offs, reference files, computer use or extra tools for an agent did nothing in conversations it already had. They now pick up the change at their next message, and lose an ability that was switched off.
- The app did not build with Xcode 26 (Swift 6.3).
- An endpoint saved without a key, the usual case for Ollama and LM Studio, failed with "No API key for provider".
- Signing in with a subscription could fail with "The stored credential is unreadable": long sign-in credentials were cut off when saved to the Keychain.
- Signing in with ChatGPT failed with "requires a device ID".

# Models on this Mac: running them

pi² can run a model on the Mac itself, with the Strata engine, and use it like any other model (#173). It is built in pieces: getting the engine and a model onto the Mac, preparing it and setting it up in Settings (#292 and #293, [local-models.md](local-models.md)), running them (#291, this page), and running the real thing through pi² (#293, [below](#checked-against-the-real-engine-293)). The two halves meet at `local-models.json` in the data folder, which the downloads piece writes and the running piece reads.

The code that runs them is `engine/src/localrun.ts`, with everything particular to the real engine in `engine/src/localengine.ts`, and the provider in `engine/src/providers.ts`. The app's side is `app/Sources/pi2/LocalModelViews.swift`.

## In the model selector

A model that is set up is always offered, under **On this Mac**, whether or not it is running. Its context size is the one it was set up with, and is what pi² goes by to decide when to summarise a long conversation. It is marked as seeing pictures when it was set up with its picture reader, and as thinking, with Off, Low, Medium, High and Extra High (sent as Strata's `reasoning_effort`; Off is `none`). Its use counts tokens only, as for any model without a price.

**A new conversation with it thinks at Low**, unless its agent has a thinking level of its own (`defaultThinking` in `providers.ts`): a conversation made with it, a chat, a sub-chat, and a conversation whose model is switched to it while it has no thinking level. Left to itself, with no `reasoning_effort`, Qwen3.8-Flash-Next thinks at length: 2,300 tokens and 31 seconds before the first word of a 200-word story, in #293 as in #290. Told any level, it thinks for a few lines: at Low, 120 to 320 characters of thinking and about a second before it answered or called a tool, on short questions, three small agent tasks with tools and the same story. Off (pi²'s default for other models, sent as `none`) is quicker still, but once answered "I'll find the largest file" without calling the tool it was given, where Low called it every time. pi² always sends a level, so the long default thinking never happens through pi². The person changes it in the conversation's toolbar, as for any model.

## When it runs

A model on this Mac starts when a conversation starts using it, and stops a minute after the last one stops.

A conversation **uses** the model while its model is that one and:

- it is open in one of the agent view's panes (whichever page the window shows, and whether or not the window is open), or is chat mode's chat on screen (whichever side the window shows, since each keeps what it shows while the other is up); or
- its agent is working: a run, a sub-chat's run, or a scheduled one, whether or not it is open.

It stops counting when its pane is closed or shows another conversation, when it is archived or deleted, or when its model is changed. An idle open conversation keeps the model loaded: it is not started and stopped between messages.

So it **starts** when a conversation with it chosen is opened or created, when a conversation's model is switched to it, or when work starts with it. The conversation says it is starting, with what the engine says it is doing ("mapping the experts") or how far it has got, and a message sent meanwhile waits and is answered once it has loaded.

It **stops** once nothing has used it for a minute, so that switching between two conversations does not unload and load it again. Activity shows the time left.

**Quitting the app** closes its panes. When the engine keeps running after the app quits (the login item, or "Keep agents running after I quit pi²"), a model only open conversations were using stops a minute later; one an agent is working with stays until that work ends. Nobody can see or type into a pane of an app that is not running, a loaded model holds tens of gigabytes, and opening the app again shows the same panes, which start it again.

**Several conversations** share the one loaded model.

## Seeing and stopping it

**Activity** has a section, **Models on this Mac**, while one runs: its name, whether it is loading or since when it has been loaded, how much memory it and what it started hold (resident, by `ps`, the model's mapped file included), how many conversations use it or how long until it stops, its log, and **Stop**. The **menu bar** lists it under Running, with Stop.

Stopping it by hand does not break the conversations using it: an answer it was giving is cut off, and the next message starts it again. It is not started again by itself for the conversations already open, only for a message, or for a conversation that starts using it.

## When it cannot start, or stops unexpectedly

If the model cannot be loaded, the conversation says why, shows the last lines the engine printed and offers its log; a message sent to it gets the same answer, with where the log is. The next message tries again. The log is `local/logs/<model>.log` in the data folder, written afresh at each start. It is not part of a backup.

If the loaded engine stops unexpectedly during an answer, each affected conversation asks again on its own, which starts the engine if needed. pi² waits about 2, 10 and 30 seconds before its three tries and says in the conversation that it is carrying on. An answer resets the count. If all three tries fail, the run ends with the reason and where to find the model's log. Stop in the conversation ends a wait immediately. If no request is in progress when the engine stops, the next message starts it again.

**Several requests at once.** A model answers up to four requests at the same moment by default (Settings › Providers › On this Mac, Requests at once). Strata's engine 0.1.60, which pi² pinned before #605, ended itself when two answers had been written side by side for a minute with no request coming in ("no progress for 60 s during a request (idle -1)", exit code -6, #424): its watchdog did not count a Mac's batch window as progress. Strata fixed it in 0.1.62, and pi² pins 0.1.63; an engine older than 0.1.62 still set up is started with one request at a time whatever the setting, and Settings says to update it. With one, conversations take turns, each keeping its place in Strata's conversation cache. With four, together they write about as fast as one alone (the Mac's engine takes the requests in turn, and without its draft layer), but an agent whose tool has finished goes on within seconds instead of waiting for the others' whole turns; each takes about 3.3 GB more at a 131K context. [strata.md](strata.md#several-requests-at-once-605) has the measurements.

## The process

pi²'s engine starts it, never the app, as it starts everything it leaves to run on its own ([background.md](background.md)): bound to 127.0.0.1 on a port pi² picks, with a key made for each run in its environment (never on its command line, which any process can read), leading a process group of its own, with the run's marker (`PI2_RUN`) in its environment and its run's file open, as the engine's other runs have them. Its group, when its first process started, and the marker are kept in a session document, `pi2.local`.

- **What it starts** is followed too. Strata's server starts its engine and picture reader in process groups of their own (#290), which a signal to the server's group does not reach. So pi² lists, every ten seconds while it runs and again as a stop begins, every process the server started, at any depth and in any group, and once the server has gone ends whatever of them is still the same process (the same number and start time). Strata's server ends them itself when asked to stop, in about two seconds, and its watchers end them within a second when it is killed ([strata.md](strata.md#stopping)); this is for when neither happens. It also lets Activity count their memory, the engine's 60 GB among it.
- A **clean stop** of the engine stops it: SIGTERM, a second and a half, then SIGKILL for whatever of its group, and of what it started, is left, inside the five seconds the app gives the engine.
- An engine that **died** (killed outright, or crashed) leaves it running for the moment. The next engine stops it as it stops a background command left that way (`stopLeftOver` in `engine/src/processes.ts`): the whole group while its first process is still the one noted, else only the processes carrying its marker or holding its run's file. What its first process started in groups of their own, listed at the moment that process is proved the same, is ended a few seconds later if it is still there. `engine.log` says what became of it.
- A stop by hand, or for want of anyone using it, gives it five seconds to end before SIGKILL. A crash of the server is followed by the end of what it started, five seconds later.

Loading may take up to 20 minutes before pi² gives up on it and says so.

## For developers

- **What is set up** comes from `local-models.json`: `{ "engine": { "version", "path", "folder", "control": { "version", "folder" }, "component" } | null, "models": [{ "id", "name", "pack", "path", "contextSize", "config", "preparedWith", "options" }] }`: the engine's executable, its whole package and Strata's control package; the model's first file and the run config Strata's setup wrote when it prepared the model (pi²'s copy of it). `localSetupReader` reads it again whenever it changes. Of `options`, `vision` and `parallel` are used; other keys are kept and ignored.
- **The engine's description** is `STRATA` in `localengine.ts`: the program, arguments and environment that serve a model on a port, why a model cannot be started as it is set up (`missing`), the variable it reads its key from, where its OpenAI-compatible API is, the path that answers 200 once it has loaded, and how far loading has got, or what it is doing, from a line it prints. Strata's setup, which the downloads piece runs, is described beside it (`STRATA_SETUP`). Nothing else assumes anything about the real engine. Strata's HTTP server is its control package's `serve/server.py`, which starts the engine from Strata's component folder with the model's run config, and every Strata command runs with `HOME`, `XDG_DATA_HOME` and `STRATA_HOME` in `local/strata/` of the data folder, `PYTHONNOUSERSITE=1` and no `PYTHONHOME` or `PYTHONPATH` (`strataEnvironment`), so nothing goes to the person's own folders and no Python of theirs is used.
- **The command line** is `<control>/python/bin/python3 <control>/serve/server.py --engine strata --config <run config> --host 127.0.0.1 --port <n> --parallel <n> --shutdown-timeout 2`, in its own process group, with the key in `STRATA_API_KEY`. The run config is written afresh at each start (`runConfig`), from the one Strata's setup wrote, to `local/run/<model>.json` (readable by the person only): `--max-context` set to the model's context size, `--vision` and the `vision` section left out while pictures are off, and the engine's own log in `local/logs/<model>.engine.log`. So Settings' context size and pictures count at the next start without preparing the model again; requests at once is `--parallel`, one with an engine older than 0.1.62 (`requestsAtOnce`). `--shutdown-timeout 2` cuts off answers still being written two seconds after a stop, inside the five seconds pi² gives the server. A model with no run config (not prepared yet, or being prepared again after an update of Strata) is not started: a message to it says it is being prepared, and Settings shows how far it has got. Until #293 such a model was started with guessed flags of the executable's own, which the real engine does not take; that is gone, and the stand-in takes the server's command line instead.
- **A request** to `local/<id>` goes through `localProvider` in `providers.ts`, an OpenAI-compatible provider like an endpoint of one's own. Before each request it takes a lease from the runner (`lease` in `localrun.ts`), which starts the model if need be, waits until it has loaded, and holds it while the request runs; the request then goes to wherever it runs now, with that run's key. A model that cannot start ends the run with the reason instead of starting it over and over. For an engine stop during an answer, `localrun.ts` uses pi-durable's stored retry sleep: each run keeps its own count, and its notice is a display-only entry placed when it asks again. If Strata's HTTP server is still up, the next request lets it restart its own engine; if the server went away, the next lease starts a server.
- **Who uses it** is worked out again whenever it may have changed: which conversations the apps show (`shownChanged`), which have work running (`runsChanged`), a model changed (`modelChanged`), a conversation archived or deleted (`putAwayChanged`), and a request ending.
- **Requests:** `conversations.shown { ids }` from the app, with the conversations in its panes (and chat mode's current chat), whenever that changes and as it connects; the engine keeps one set for each connection, so an app that quits shows nothing. `local.start { id }` starts a model and answers once it is ready, or with why it is not (Settings' Try it). `local.stop { id }` is the person's Stop. `local.status` (localmodels.ts) answers what is set up and, from this feature's `localStatus()`, `running` and `ended` below; a change to them sends `local.running`, and `local` through `localChanged()`.
- **Events:** `{ "event": "local.running", running, ended }` on every change and to each app as it connects. A running entry is `{ id, name, status: "starting" | "ready" | "stopping", startedAt, readyAt, progress, stage, memory, pid, users, stopsAt, log, recorded }`: `progress` from 0 to 1 when the engine says, `stage` what it says it is doing while it loads, `memory` the bytes it and what it started have resident (by `ps`), `users` the conversations using it, `stopsAt` when it stops unless someone uses it by then, `recorded` whether its process is on record for the next engine. `ended` says, for each model, how its last run ended: `{ at, how, failed, lines, log }`.
- **A conversation's state** has `local: { model, name, status: "starting" | "ready" | "stopping" | "stopped" | "failed", since, progress, stage, error, lines, log }` when its model is on this Mac, and `null` otherwise.
- **The test** is `engine/test/localrun.ts`, with a stand-in for the engine, `engine/test/localserver.ts`, that takes the same command line, serves the same API, loads only once the test lets it, and can be told to fail to load, to crash in the middle of an answer, to hold an answer, to start a program of its own in a group of its own (as Strata's server starts its engine) and to ignore SIGTERM. `PI2_LOCAL_GRACE_SECONDS` sets the grace period, which the test makes an hour for one engine and nothing for another.

## Checked against the real engine (#293)

On the M5 Max with 128 GB, macOS 27.2, on 2026-11-18, Strata 0.2.15 (engine 0.1.60, control 0.1.61) and Qwen3.8-Flash-Next IQ3_S at a 64K context, in a throwaway copy of a development build, set up through Settings from the files #290 left on the Mac:

- **Setting up.** Get Strata downloaded the two archives from their pinned URLs (GitHub's redirect to its object store), checked, unpacked and installed the engine into Strata's component folder in under 30 seconds. The model's 84.5 GB were cloned from the trial's folder and checked in about 20 seconds, the draft layer's tensors taken from there too, and Strata's setup prepared the pack in 55 seconds, its steps shown in the row. The download sheet showed the Qwen licence's second clause in full. The folder was given through the engine's socket: the Open panel that Agree and Use Files on This Mac… shows came up, but choosing a folder in it by clicking was not tried.
- **Try It** started the model and showed "It answered: “Hello there, I am fully set up and ready to help you with your work!”" about 15 seconds after the click.
- **Starting.** Ready 6 to 32 seconds after it was started, every time: the Metal kernels had been compiled already, in #290, and macOS kept them, so the three-minute first start was not seen again. Readiness by `/v1/models` works (the port opens only once the model is loaded), so the ready file is not needed. What the server prints while it loads is plain lines, `[strata] mapping the experts …` and the like, which the conversation and Settings show as the stage.
- **A conversation** (Scout, switched to the model in the toolbar, which then showed Thinking: Low) answered "What files are in your folder right now? Look, then tell me in one sentence." by calling `list_files`, then "The folder is empty — list_files returned 0 entries…", with its thinking shown as Thought rows.
- **Two conversations at once**, each asked for a 150-word paragraph at the same moment: both answered in full, one after the other (one request at a time is the default), 32 and 26 seconds each, at 53 to 60 tokens a second on a Mac busy with other work.
- **Stopping when the last closes.** With the pane showing another conversation (on the demo model), Activity counted down and the model stopped 60 seconds later, "was stopped because no conversation was using it"; the server, the engine, the picture reader and both watchers were gone.
- **Stop in Activity** stopped it ("stopping", then gone in under four seconds); the conversation using it was not started again by itself, and its next message started it and was answered.
- **kill -9 of the copy's engine** with the model loaded: the app started a new engine at once, which logged "left by the last engine, was stopped": the server and everything it started were gone within two seconds, and a new server started for the conversation still shown. The old server's last line ("[strata] stopped") landed in the new run's log, which is why each run's log is now a new file rather than the old one emptied.
- **A clean stop** of the engine (SIGTERM) stopped the model with it, "stopped cleanly in 802 ms", and the next engine started it again for the conversation shown.
- **Memory.** Activity showed 59 to 64 GB (`ps`'s resident memory of the server and all it started, which counts the 55 GB model file mapped for the GPU); Activity Monitor's Memory column showed 14 GB for `strata`, 1 GB for `strata-vision` and about 230 MB for the server. Activity now says the figure includes the model's file. With `--mmap-experts`, the file's pages are in the file cache rather than wired: wired memory stayed about 5 GB.
- **Thinking**: see [In the model selector](#in-the-model-selector).

Not tried: `parallel` above 1 through pi² (#290 tried `--parallel 2` on the server itself), pictures sent from a conversation, the conversation's strip during a slow first start, a model stopping while it answers, and a long agent session.

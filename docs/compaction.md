# Summarizing earlier messages

A model reads the active conversation again on every request, even when parts come from its prompt cache. A summary replaces an older part of that context, not the transcript you can still read. It trades away detail and usually writes the prompt cache again once, but later requests can read less.

## When it happens

- **At a size you choose.** Settings › General › Long conversations has **Summarise earlier messages when a conversation reaches…**, the default for all agents: off, or 50,000, 100,000, 200,000, 300,000 or 500,000 tokens. Each agent's page has the same sizes under Long conversations, with **Use the default** first, which inherits the default for all agents, and **Off** next, which never summarises earlier than the model's own limit, whatever the default is. A size that does not bring the normal threshold forward changes nothing. The limit is an estimate for the next request, not a hard cap: there must be older messages to cut without splitting a tool call and its results. A small target also keeps a smaller recent tail verbatim. The chat-mode assistant does not use the agent default.
- **When you ask.** Choose **Summarise Earlier Messages** after the conversation finishes answering. If there is no older part to summarise, the conversation shows “There is too little here to summarise yet.” Nothing is added to what the model reads. You can retry if it is already summarizing or there is a model error.
- **When an agent asks.** Enable **Summarise its own conversation** in the agent’s built-in tools. `compact { note }` runs at the end of the current round of tools, before the next model step. It is off by default. The note says what must be kept, and the conversation marks the summary as requested by the agent. More than one request in a round shares a summary, with the notes in call order. A script cannot call it as a nested tool.

## What stays

The summarizer is told to keep the person's unfinished requests and constraints, what they asked the agent to remember, what the agent said must be kept, decisions, progress, blockers and next steps. This part is a model's account of the conversation and can lose detail. Earlier messages are still readable if you need to check them.

After the model writes, pi² adds what it knows itself: open sub-chats and their tasks and standing, running background commands and whether their ends are watched, pending wakes and any hold, the current task list, and the agent’s explicit compaction notes verbatim. This is taken from the engine’s records in the same commit as the summary marker, not copied by the model. The explicit notes carry forward through later summaries in the active context. In a project's conversation with its orchestrator, with projects on, it ends with the project as it stands: who is working, what waits for the person, the reports not read, the work and the person's messages to other agents not yet given ([projects.md](projects.md#64-the-catch-up-and-the-state-block)). A summary does not count as telling the orchestrator what changed: that still comes at the start of its next turn.

A message sent during a summary is kept in the conversation’s queue; a wake stays in the wake queue. The summary finishes before either is delivered, and normal steering and wake ordering still applies. If a summary fails, pi² reports the error and does not move the context head or write a summary marker. A failure at the model’s hard context limit can still prevent the run from answering; the transcript and queued input remain available under the normal failed-run rules.

## In the app

- **Settings › General** (`CompactionDefaultSettings` in `CompactionSettings.swift`) shows the default from the `compactionSettings` event and changes it with `settings.setCompaction`. The footer says what the chosen size means ("larger than 100,000 tokens, about 75,000 words of English", at three-quarters of a word a token) and what a summary trades: later turns read less, detail is lost, the next turn writes the cache again, and the earlier messages stay readable. A size set some other way, such as through the engine's socket, is listed with the others rather than replaced.
- **An agent's page** (`AgentCompactionSection`, `PI2_SHOW=agent:<id>#summaries`) saves the choice as `compactionTokens` with the rest of the agent; **Use the default (…)** names the default it inherits and saves `null`. **Off** comes next and saves `0`: the footer says its conversations are summarised only as they near their model's limit, whatever the default. The footer also points to the built-in tool.
- **The built-in tool** is listed with the others from the engine's `builtInTools`; the app has no switch of its own for it. The call's row reads "Asked for earlier messages to be summarised" and opens to the note.
- **The transcript** draws a summary's line from `details.compaction`, not from the engine's `text` (`compaction` in `app/Web/transcript/tools.js`): "Earlier messages summarised by pi² at the size you set", "…, as you asked", "…, as <agent> asked" or "… by pi² as the model’s limit neared". A note is shown under the line, labelled as the agent's or yours. A manual request with too little to summarise shows a plain notice in the transcript instead of a summary marker.
- **The size of the last request** (`lastRequestInputTokens`) is a line in the context menu of the conversation's toolbar, under the context line: "Last request read 42k tokens".

## Engine contract

- **Default:** `defaultCompactionTokens` in `settings.json`. `settings.getCompaction {}` reads it; `settings.setCompaction { defaultCompactionTokens }` writes it. Both return `{ defaultCompactionTokens }`. `compactionSettings` events carry that field on connect and on change. Use a positive safe integer for a size or `null` for Off.
- **Per agent:** `compactionTokens` in the saved agent profile (`pi2.agents`). Read it on the agent in the `agents` event and write it with `agents.save { agent: { id, name, compactionTokens } }`. Use a positive safe integer for a size, `0` for Off (no earlier threshold even when the default is on), or `null` to inherit. A missing saved field also means inherit. The engine resolves the effective threshold against the current model, including model changes. To enable the separate tool, include `compact` in `toolsOn` when saving the agent. The `agents` event advertises the built-in key and its default.
- **Marker:** A transcript item with `kind: "marker"`, a display `text`, and `details.compaction: { trigger, note }`. `trigger` is `"size"`, `"person"`, `"agent"` or `"automatic"` (the model-window safeguard, including old automatic markers). `note` is a string or `null`. When `conversation.compact` finds no eligible cut, it adds a display-only `kind: "marker"` notice without `details.compaction` and leaves the model's context unchanged.
- **Size:** Conversation state has `lastRequestInputTokens`, the input, cache-read and cache-write tokens of the last ordinary model request with usage. It excludes output and the separate summary request, and is `null` when no usage is known. It is not a prediction of how large the next request will be. `context.used` remains the existing context indicator.

Pi durable still selects the cut, runs the summarizer, accounts for its usage, and owns the durable runs and queues. `engine/scripts/patch-compaction.ts` supplies the earlier per-model reserve and tail settings without changing the ordinary answer reserve or summary budget, adds safe boundaries for the tool and for standalone summaries, and attaches the state snapshot at placement. The normal near-window thresholds are unchanged, but a summary started there no longer races the next request.
